# 0002: Set a personal design direction

- Status: Accepted
- Date: 2026-09-23

## Why this decision exists

A portfolio can look polished and still feel anonymous.

This site should feel like Ahammed's work. It should not look like a copy of another website or an AI-generated theme.

We need to agree on that direction before choosing colors, type, layouts, components, or motion.

## The statement

> I want this site to feel like a clear conversation about my work.
>
> It should show technical depth without pretending to be a terminal.
>
> It should be precise without feeling cold.
>
> It should try new ideas without becoming unreliable.
>
> It should show strong evidence without becoming hard to scan.
>
> It should stay quiet without feeling empty.

## The five checks

Every major design choice must support at least one of these goals.

| Goal                                | Use                                                          | Avoid                                               |
| ----------------------------------- | ------------------------------------------------------------ | --------------------------------------------------- |
| Technical, not fake-terminal themed | Real diagrams, measurements, code, and project details       | Fake prompts, blinking cursors, and decorative code |
| Precise, not cold                   | Clear order, careful spacing, exact words, and useful detail | A generic design with no personal voice             |
| Experimental, but reliable          | Small, tested ideas with simple fallbacks                    | Effects that hurt access, speed, or understanding   |
| Detailed, but easy to scan          | Short summaries, clear headings, and links to proof          | Long walls of text or claims with no proof          |
| Quiet, but not empty                | Restraint with enough information to stay useful             | Clutter or large empty areas with no purpose        |

Major choices include type, color, layout, navigation, components, images, and motion.

## How a design choice is made

1. Start with a real visitor need or piece of evidence.
2. Use a reference chosen by Ahammed and explain why it matters.
3. List the limits the design must respect.
4. Write a simple rule for this site.
5. Let Ahammed and another person review the result.

AI may help find problems, compare options, and run checks.

AI may not invent personal details, choose the site's personality, or make the final decision.

## What this changes

- Visual work waits until Ahammed approves this statement and shares the first personal references.
- PlanetScale may provide useful technical ideas, but it does not define this site's identity.
- Existing ideas about color, type, layout, and motion must pass the five checks before they become code.
- Accessibility, clear HTML, speed, and no-JavaScript support remain required.
